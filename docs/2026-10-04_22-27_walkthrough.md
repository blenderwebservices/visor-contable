# Reporte de Entrega: Corrección de Falla al 24% en Restauración de Respaldos

**Fecha y Hora:** 2026-10-04 22:27  
**Rama:** `main`  
**Problema Atendido:** Falla en la subida de archivos de respaldo al 24% con el error `The mountedActionsData.0.documents_file... failed to upload` ("Error durante la subida (7.3 MB)").

---

## 1. Causa Raíz Detectada

El fallo al 24% se debió a una combinación de tres cuellos de botella y límites restrictivos en el stack del servidor y la aplicación:

1. **Límite de PHP en Herd (`upload_max_filesize` y `post_max_size` en 2M):**
   - El archivo `php.ini` de Herd (`~/Library/Application Support/Herd/config/php/84/php.ini`) tenía por defecto `upload_max_filesize = 2M` y `post_max_size = 2M`.
   - Con un archivo de **7.3 MB**, el 24% equivale exactamente a **~1.75 MB**. Al sumar las cabeceras HTTP y el límite de 2MB, PHP abortaba la transferencia con el código de error `UPLOAD_ERR_INI_SIZE`, provocando que Livewire recibiera un archivo no válido (`!$file->isValid()`) y detonara el mensaje de error de validación `uploaded`.

2. **Límite de Nginx en Herd (`client_max_body_size` en 2M):**
   - En `~/Library/Application Support/Herd/config/nginx/herd.conf`, la directiva `client_max_body_size` estaba configurada en `2M;`.

3. **Límite por Defecto de Livewire (12 MB):**
   - En Livewire 3, si no existe el archivo de configuración `config/livewire.php`, la regla predeterminada de subida temporal limita los archivos a `max:12288` (12 MB), lo cual bloquearía cualquier respaldo completo de mayor volumen (por ejemplo, 30MB, 50MB o 200MB).

4. **Componentes FileUpload de Filament en `Settings.php`:**
   - No contaban con un `maxSize(...)` explícito para respaldos pesados.

---

## 2. Cambios Implementados

### 1. Actualización de Directivas en PHP (`php.ini` de Herd)
Se actualizaron los archivos `php.ini` en las versiones de Herd (incluyendo la versión activa PHP 8.4):
- `upload_max_filesize = 512M`
- `post_max_size = 512M`
- `memory_limit = 512M`
- `max_execution_time = 300`

### 2. Actualización de Nginx en Herd (`herd.conf`)
Se actualizó `client_max_body_size` a `512M;` en:
- `~/Library/Application Support/Herd/config/nginx/herd.conf`
- Se reiniciaron los servicios de Herd (`herd restart`).

### 3. Publicación y Configuración de Livewire (`config/livewire.php`)
Se publicó `config/livewire.php` configurando:
```php
'temporary_file_upload' => [
    'disk' => null,
    'rules' => ['required', 'file', 'max:512000'], // Soporte de hasta 500 MB
    'directory' => null,
    'middleware' => null,
    'preview_mimes' => [ ... ],
    'max_upload_time' => 30, // 30 minutos de tiempo de subida
    'cleanup' => true,
],
```

### 4. Actualización de `app/Filament/Pages/Settings.php`
Se agregó `->maxSize(512000)` (500 MB) a las acciones de importación:
- `import_full_backup` (`full_backup_file`)
- `import_backup` (`backup_file`)
- `import_documents` (`documents_file`)

### 5. Pruebas Automatizadas
Se implementó `tests/Feature/BackupUploadLimitTest.php`:
- `test_livewire_allows_large_file_uploads_up_to_500mb`: Valida que Livewire tenga activas las reglas para permitir hasta 500MB.
- `test_livewire_temporary_upload_endpoint_accepts_file_larger_than_two_megabytes`: Valida que el endpoint de subida temporal de Livewire acepte archivos ZIP de 8MB sin fallar.
- `test_settings_page_can_import_documents_zip`: Valida que la acción `import_documents` procese correctamente el archivo ZIP y sincronice los archivos en el almacenamiento.
